# Breezyfy

Free, browser-local visible Gemini watermark cleanup for `breezyfy.com`, with an original responsive interface. Support: **korisolution@gmail.com**.

**Important:** this is an independently implemented website, not an exact Erasio clone. REA verified public browser code and the core processing category. Complete A–Z equivalence, proprietary calibrations, the separate Veo/Omni engine and opaque-fill features were **not** established or reproduced. See [feature coverage](docs/FEATURE-COVERAGE.md) and [REA evidence summary](docs/REA-FINDINGS.json).

## Included

- PNG, JPEG, WebP and supported BMP images; MP4 video on compatible WebCodecs browsers.
- Local reverse alpha blending with licensed compact/classic/May-2026 calibration maps.
- Original/result previews, image comparison slider, individual downloads and ZIP.
- Sequential mixed-media batch, progress, cancel/retry and per-file errors.
- Profile, strength, scale, threshold, feathering, offsets and manual image positioning.
- PNG/JPEG/WebP export, quality and image resizing.
- Light/dark themes and optional saved removal preferences.
- Terms, privacy, acceptable use, storage notice, guide, technology, FAQ and contact pages.
- No login, payments, subscriptions, ads, analytics or admin panel.

Files are processed on the visitor's device; there is no media-upload backend or API key. Hosting still receives normal website requests. The exact supported limits and missing comparison features are in `docs/FEATURE-COVERAGE.md`.

## Local development

Use Node.js 22.12+ or 24 LTS and npm. Node 24.18 was used for validation.

```sh
npm ci
npm run dev
```

Open the URL printed by Vite, usually `http://127.0.0.1:5173/`. Do not open `index.html` directly with a `file://` URL.

```sh
npm test
npm run build
npm run preview
```

The production website is generated in `dist/`. Video code is loaded when needed. Fonts, masks and libraries are bundled locally. License notices are generated by `scripts/notices.mjs` and included in the deployed site.

## Aapke existing GitHub + Vercel setup mein lagana

Hosting aur domain wahi reh sakte hain. Yeh React/Vite project hai, isliye **sirf purane `index.html` mein code paste karna kaafi nahi hai**.

1. Apne existing GitHub repo `emsid704/breezyfy` ka current version backup/recoverable rakhein. Naye code ke liye ek branch banayein, jaise `breezyfy-redesign`.
2. `breezyfy-source.zip` extract karein. Iske root files aur folders ko repository root mein upload karein: `package.json`, `package-lock.json`, `index.html`, `vite.config.ts`, `tsconfig.json`, `vercel.json`, `src/`, `public/`, `scripts/`, `licenses/`, `docs/` aur `tests/`.
3. `node_modules`, `.research`, `.qa`, `.env` ya ZIP file ko repo mein upload na karein. Existing old admin code is release ka part nahi hai; use backup branch mein preserve karein. Naya build sirf `dist/` deploy karta hai.
4. Usi Vercel project mein settings check karein: **Framework Preset: Vite**, **Install Command: `npm ci`**, **Build Command: `npm run build`**, **Output Directory: `dist`**, **Root Directory: repository root**. `vercel.json` is project ki build/routing configuration deta hai.
5. Branch ka Vercel preview open karke image, video, downloads, `/terms`, `/privacy` aur mobile layout check karein. Satisfied hone ke baad branch ko production branch mein merge karein.
6. `breezyfy.com` agar already isi Vercel project se connected hai, normally wahi domain deployment serve karega. Domain/DNS tab ko verify karein; bina zaroorat naya hosting project ya DNS change na karein.

Is task mein live repo push, production deployment, domain transfer ya DNS change **nahi hua**. Existing production remains recoverable through your current GitHub/Vercel history.

Official deployment references: [Vercel Vite guide](https://vercel.com/docs/frameworks/frontend/vite), [Vite static deployment](https://vite.dev/guide/static-deploy.html), [Vercel project configuration](https://vercel.com/docs/project-configuration).

## Browser checks

Start `npm run dev` in one terminal, then:

```sh
npm run test:browser
npm run test:ui
```

Tests use installed Google Chrome by default on Windows. Set `CHROME_PATH` to your Chromium executable elsewhere; `TEST_URL` selects another local server. Engine tests deliberately need the Vite dev source paths. UI tests can also run against a production preview and need the synthetic fixtures included under `tests/engine-fixtures/`.

These tests use artificial, licensed-mask overlays, including an MP4 with generated audio. Passing tests do not guarantee removal on every real Gemini/Flow version. See `docs/VALIDATION.md` for evidence and limits.
